## Context

**WI-0004, round 1, question 2 of 3.** Same item, same round; this one is about how far the rule
reaches once a cell qualifies.

You wrote: *"Markers are for normal cells, not those."* That sentence can mean the marker stops
applying to **that cell**, or that a column containing such a cell stops being a marked column
altogether. The two produce visibly different tables, and only one column in a real document is
usually affected, so it is not a corner case — it is what most of these tables will look like.

Take a centred column with one multi-line cell and two ordinary ones. Under the first reading:

```
| items      | n |
|:----------:|--:|
|   apple    | 1 |
| pear<br>fig | 2 |
|   plum     | 3 |
```

— the multi-line cell sits left, `apple` and `plum` stay centred. Under the second:

```
| items       | n |
|:-----------:|--:|
| apple       | 1 |
| pear<br>fig | 2 |
| plum        | 3 |
```

— the whole column goes plain, marker still written, nothing in it centred. (Both are sketches of
the two rules, not tool output: the tool does neither today.)

## Question

**When a cell contains a line break, does only that cell stop obeying the column's marker, or does
the whole column?**

## Options considered

- **A — only that cell.** Its neighbours above and below go on being centred or right-aligned as
  the marker says. Consequence: the marker keeps meaning what it means everywhere it can, and the
  exception is exactly the cells you described. The column can look ragged, because one row starts
  at the left while the others are centred — which is the first sketch above.
- **B — the whole column.** One cell with a line break makes the column plain: every cell in it
  pads to the right, the marker stays written in the delimiter row but nothing obeys it.
  Consequence: the column reads evenly, all its cells starting at the same place. The cost is that
  adding a `<br>` to one cell silently changes how every other cell in that column is laid out —
  including cells the author never touched.
- **Recommendation: A.** *"Markers are for normal cells, not those"* reads as a statement about
  the cells rather than about the column, and A is the reading where one edit changes one cell. B
  is defensible if what bothers you is a column that does not line up down its left edge; if that
  is the point, say so and A is wrong.

## Answer

[human] Only that cell. Putting a break in one row must not go and shift rows I never touched —
that is exactly the kind of surprise I do not want from this thing. A ragged-looking column is
fine; it is telling me the truth about what is in it.
