## Context

WI-0001, refinement round 1, question 2 of 3 — one conversation with question 1 and question 3.

You told us the tables you care about are "the pipe ones, the ones with the dashes under the
header" (`EP-001/Q-002`). That leaves one thing open, because the same syntax is written two
ways in the wild:

```
| name | role     |          name | role
|------|----------|          -----|---------
| Ada  | engineer |          Ada  | engineer
```

Both render identically. The one on the right has no leading or trailing `|`, which GFM allows.
The tool has to decide whether the right-hand form is a table at all, and if it is, whether the
output keeps that style or gains the outer pipes.

We are asking rather than deciding because it turns on which of these you actually write, and
because the answer can change bytes on lines you did not expect to change: adding outer pipes to
a table that never had them is a visible edit to your document. That is the same escalation
condition as before — intent about your own files (`spec/question.md` §4).

## Question

Is a pipe table written without outer `|` characters one of the tables this tool should align,
and if so, should the output keep that style or add the outer pipes?

## Options considered

- **A — Recognise it, and preserve the style each table already uses.** A table with outer pipes
  keeps them; one without stays without. Consequence: the tool never adds or removes a character
  you did not have, and both styles align. It is slightly more work and means the layout code
  carries a per-table flag.
- **B — Recognise it, and normalise everything to outer pipes.** Consequence: every table in
  your documents comes out looking the same, which is what most formatters do; the cost is that
  running the tool over a document written in the bare style rewrites every table row in it, so
  the first run produces a large diff.
- **C — Only treat the outer-pipe form as a table; leave the bare form alone.** Consequence:
  simplest to specify and the tool touches less; if you do write bare tables, they silently stay
  ragged and nothing tells you why.
- **Recommendation:** **A**. It aligns everything you write while keeping the tool's promise
  that it changes spacing and not content, and it avoids handing you a diff that touches tables
  you were happy with. Choose B if you would rather all your tables end up in one house style,
  and say so — that is a preference we cannot read off your documents.

## Answer

[human] Yes, that's still a table and it should line up. But whichever way I wrote it is the way
it stays — if I didn't put the outer bars in, don't add them for me. I only want the spacing
changed, never the punctuation.
