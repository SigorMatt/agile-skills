## Context

WI-0001, refinement round 1, question 3 of 3, and that is all of them for now.

A pipe table does not always start at column one. It can sit inside a blockquote or inside a
list item, where every line carries a prefix:

```
> | name | role     |
> |------|----------|
> | Ada  | engineer |

- Some point I am making:
  | name | role     |
  |------|----------|
  | Ada  | engineer |
```

These are still tables and still render as tables. The tool currently has no criterion covering
them, so as written it would treat those lines as ordinary prose and leave them ragged. Aligning
them is not free: the tool has to recognise the prefix, strip it, lay the table out, and put the
prefix back on every line — and it has to leave alone anything where it cannot do that
confidently.

This is question 3 of the item's Definition of Ready R10 check: it is a combination of two
constructs whose behaviour together is currently unspecified, and R10 requires that it be
decided, excluded, or written down as deliberately open. We would rather you decided it than
find later that half your tables were skipped.

## Question

Should the tool lay out a pipe table that is indented inside a blockquote (`> `) or a list
item, or should it leave indented tables alone?

## Options considered

- **A — Handle both: a blockquote prefix and a list indent.** Consequence: every table in your
  documents gets aligned wherever it sits. It is the largest of the three in build cost, and it
  adds a class of edge cases — nested quotes, a table whose rows carry inconsistent prefixes —
  each of which needs a rule of its own.
- **B — Handle a uniform indent only** (every line of the table carries the same leading spaces
  or the same `> ` prefix), and leave anything else untouched. Consequence: covers the two
  cases above and the great majority of real documents, with one rule — "strip the common
  prefix, lay out, restore it" — rather than a family of them.
- **C — Only lay out tables that start at column one.** Consequence: the smallest thing that
  works, and the easiest to be sure is correct; tables in quotes and lists stay ragged for ever,
  with no message saying so.
- **Recommendation:** **B**. It is the same amount of specification as C for nearly the coverage
  of A, and the rule it needs is one a reader can check. Choose C if you never put tables in
  lists or quotes and would rather the tool stayed small; choose A only if you know you have
  nested or irregular cases.

## Answer

[human] Align them. I put tables under bullet points all the time and quote them in notes, and a
table that's indented is still a table — it would be odd if those were the ones that stayed
ragged. If a table is indented in some tangled way you can't make sense of, that's one you leave
alone, same as any other table you don't understand.
