## Context

You asked for this, in one sentence:

> *"A filter that reads markdown on stdin and pretty-aligns its tables: pads columns, honours
> alignment markers, leaves non-table content untouched."*

And when we asked how it should be built and what should count, you said three more things that
shaped everything after them: *"Python, and nothing I have to install first… I want to clone this
and pipe a file through it the same minute"*; *"The pipe ones, the ones with the dashes under the
header… a table inside a code fence is text I typed on purpose; don't touch it"*; and *"It has to
line up on the screen. My tables have accented names and the odd emoji in them… Measure what the
character actually takes up in my editor, not how many of them there are."*

All the work is finished. Nothing is running, nothing is waiting on us, and there is no question
outstanding anywhere in this engagement. Before we close it, you get the last word — this is the
one decision in the process that is not ours to make.

**Here is what you can do with it right now**, from a clone of this repository, with no install
step:

```
$ printf '| name | qty | price |\n|:---|---:|:---:|\n| widget | 3 | 1.50 |\n| a much longer name | 12 | 22.00 |\n' | python3 -m mdtab
| name               | qty | price |
|:-------------------|----:|:-----:|
| widget             |   3 | 1.50  |
| a much longer name |  12 | 22.00 |
```

Left, right and centre all sit where the markers ask. Accented and emoji tables line up too — we
ran `| 名前 | café | 🎉 |` through it and the bars form straight lines on screen. Prose, lists,
indented code and pipe tables inside a code fence come back byte for byte. Running it twice gives
the same bytes as running it once. It imports `sys`, `re` and `unicodedata` and nothing else;
there is no `setup.py`, no `requirements.txt`, nothing to install.

**One thing changed along the way that you decided, and it is worth seeing again**, because it is
the only case where the tool now touches a table it used to leave alone. A table written without
outer bars whose rows carry different numbers of leading spaces gets tidied back to the indent its
rows share:

```
$ printf '  a | b\n---|---\n  ccc | d\n' | python3 -m mdtab
a   | b
----|--
ccc | d
```

You were shown that exact document and said *"a table with two spaces on one row and none on the
next isn't tangled — it's just untidy, which is the exact thing I wanted the tool for."* Tabs and
quote marks are still compared exactly, as you asked, so a table indented with a tab on one row
and spaces on another is still left completely alone.

## Question

This engagement has three child items and no others. All three are closed and delivered:

- **WI-0001 — Align table columns in a stdin-to-stdout markdown filter.** **Delivered.** The
  filter itself: it finds GFM pipe tables, pads every column to a common width measured by how
  much room the characters take up on screen, and copies everything else through byte for byte —
  including anything it does not recognise as a table, silently.
- **WI-0002 — Honour the alignment markers in a table's delimiter row.** **Delivered.** `:---`,
  `---:` and `:---:` now put the text where they say, in every column including the first and the
  last, and the markers survive in the delimiter row.
- **WI-0003 — Recognise a table mdtab laid out with a right-aligned first column.** **Delivered.**
  The fault you refused to have worked around — *"if the tool then can't recognise a table it laid
  out itself, that's a fault in the tool and I'd want it sorted"* — is fixed. mdtab now goes on
  tidying the tables it lays out itself.

Nothing was dropped, nothing is blocked, and no bug was filed and left unfixed.

**Do you accept this engagement as it stands, and may we close it?**

If it helps you decide, five things we know are true and have not been asked of us. None of them
is a defect; each is somewhere the tool has not been pushed, or a decision we made on your behalf
that you may want back:

1. **There is no README and no `--help`.** You get the behaviour, not documentation of it. Nobody
   asked for either.
2. **The tool is silent about everything, always.** When it meets a table it does not recognise it
   says nothing and exits 0, which is what you asked for — but it also means there is no way to
   ask it *why* it left a table alone.
3. **Emoji made of several joined characters** (a flag, a family, an emoji with a skin tone) may
   still not line up perfectly, because there is no way to know how wide your editor draws them.
   Ordinary accented letters, CJK and single emoji are handled.
4. **Nothing large or unusual has been through it.** The biggest document any test has used is
   about 30 lines. It has not been run on a 5 000-line file, and nobody has tried to break it.
5. **Only Python 3.12 has actually run it.** We wrote it to work on 3.8 and checked that by
   reading, not by running, because no older interpreter is installed here.
