```
$ printf '| name | qty | price |\n|:---|---:|:---:|\n| widget | 3 | 1.50 |\n| a much longer name | 12 | 22.00 |\n' | python3 -m mdtab
| name               | qty | price |
|:-------------------|----:|:-----:|
| widget             |   3 | 1.50  |
| a much longer name |  12 | 22.00 |
```

**What was wrong, in plain terms.** Our own notes said, as a flat statement, that how wide a
column comes out never depends on the alignment marker you write under it. Almost always true —
but not for a column whose cells are all empty, where the marker itself needs the room:

```
$ printf 'a | | b\n---|---|---\nc | | d\n' | python3 -m mdtab
a |  | b
--|--|--
c |  | d

$ printf 'a | | b\n---|:-:|---\nc | | d\n' | python3 -m mdtab
a |   | b
--|:-:|--
c |   | d
```

Same content, one column wider, because `:-:` needs three characters to survive in the row of
dashes and `---` needs two. **The tool is right** — it has to keep that room or running it twice
would keep growing the table — and it was our description of it that was wrong. So the fix was
three sentences corrected and a test added that fails if anyone ever "fixes" the code to match the
old sentence. Nothing you would notice from the outside; but the next person to change that part
of the tool would have been reading a false statement about it, and the whole point of these notes
is that they are true.

Nothing is running now, nothing is waiting on us, and there is no question outstanding anywhere in
this engagement other than this one.
