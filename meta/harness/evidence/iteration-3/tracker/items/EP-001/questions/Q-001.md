## Question

What must this tool be written in, and what may a user be assumed to already have installed in
order to run it?

## Options considered

- **A — Python 3, standard library only, no third-party dependencies.** Consequence: runs
  anywhere Python 3 is present, which is most developer machines and nearly every Linux box;
  invoked as `python3 mdtab.py < in.md` or via a small shebang script on `PATH`. No install
  step, no package manager. Startup is a few tens of milliseconds, which is irrelevant for a
  filter run by hand and noticeable if it is ever run in a tight loop over thousands of files.
- **B — Node.js, no third-party dependencies.** Consequence: natural if this is destined to sit
  alongside other JavaScript tooling or to be published to npm later; requires Node installed,
  which is common but less universal than Python on servers.
- **C — A compiled binary (Rust or Go).** Consequence: fastest, single file, nothing to install
  for the user — but the user needs a toolchain to build it, or we need a release/distribution
  story, which is work this epic has not scoped and which would need its own item.
- **D — No preference; the team chooses and records the reasoning as an ADR.** Consequence: we
  pick during `plan` on technical grounds and write it down; you accept whatever runtime that
  implies for users.
- **Recommendation:** **A**. The tool is a text filter of modest size with no performance
  requirement anyone has stated, Python 3's standard library covers everything it needs, and it
  gives users the shortest path from "clone" to "pipe a file through it" with no install step
  and no distribution work. Choose C only if you expect this to be run over large batches of
  files where process startup would dominate.

## Answer

[human] Python, and nothing I have to install first. Every machine I work on already has Python
on it, and I want to clone this and pipe a file through it the same minute. The rest of how it's
built is your call, not mine.

**Recorded by answer-questions (architect).** The stakeholder chose option **A** and delegated
everything below it — "the rest of how it's built is your call". The two things they fixed are
the runtime (Python 3) and the absence of an install step; both are now constraints in
`ADR-0001`, which also records what remains `plan`'s to decide: entry point, module layout, test
framework, and the minimum interpreter version. A developer-only test dependency does not breach
"nothing I have to install first"; a runtime dependency does, and `ADR-0001` says so explicitly
so that `plan` cannot read the delegation as permission to add one.
