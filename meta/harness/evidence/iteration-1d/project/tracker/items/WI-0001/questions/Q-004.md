## Context

AC6 says that after you quit and start the tool again, the same people and expenses are listed.
That is the persistence requirement from your idea ("data must survive between runs") and it is
decidable as written.

What is not written anywhere is **where** the data lives, and that turns out to be a question for
you rather than for the architect, for one reason: it determines whether you can keep more than
one set of books. If the location is fixed, there is exactly one ledger on your machine, ever. If
it can be pointed somewhere else, you can keep this trip's expenses separate from the flat's.

The epic currently puts "more than one group's books in one place" out of scope, so I am not
proposing groups as a feature — only asking whether the plain file the data sits in is somewhere
you can choose.

Where exactly the file goes, and what format it is in, is the architect's decision and I am not
asking you that.

## Question

Should the tool always read and write one fixed data file, or should you be able to point it at a
different file — so that, for example, a weekend away has its own separate set of books?

## Options considered

- **A — one fixed location, not configurable.** Consequence: nothing to type, nothing to explain,
  no way to accidentally write to the wrong ledger. One set of books forever; separating a trip
  means moving the file by hand.
- **B — a fixed default, overridable per run** by an option on the command or an environment
  variable. Consequence: the common case stays zero-effort, and a separate ledger is one flag
  away. It also makes the tool far easier to test, because a test can point it at a scratch file
  instead of touching your real data — which is worth something to you indirectly, since it means
  the tests that check AC6 are real ones.
- **C — the location is always stated explicitly**, every run. Consequence: never ambiguous, and
  the most typing of the three for something you will almost always want to be the same.
- **Recommendation:** **B.** It costs one option, it keeps the no-arguments case identical to A,
  and it is the difference between "the tests exercise the real persistence path" and "the tests
  either mock it or write to your actual ledger". If you say A, I will record it and the tests
  will have to work around it.

## Answer

[human] Being able to point it at a different file would be handy — like a separate one for a
trip. Otherwise just use a sensible default.

**Recorded by `answer-questions`:** this selects **option B** — a default location used when
nothing is stated, overridable per run. What the default location is, and by what mechanism a run
points elsewhere (a flag, an environment variable, or both), remain `plan`'s to decide; the
question deliberately did not ask the stakeholder that, and the criterion is written so that it
does not presume an answer.
