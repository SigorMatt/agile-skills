## Context

This is question 2 of 3 that intake is asking about EP-001, "Pretty-align markdown tables from a
stdin filter", in one round; they are meant to be read together and answered in one sitting.

The repository is empty apart from the pipeline's own tracker and docs — no source, no build
file, no test runner, no dependency manifest. `tracker/project.yaml` has `commands.test`,
`commands.lint` and `commands.build` all set to `null`. So nothing in the project constrains what
this is written in or how it is run, and we have no basis in any document for choosing.

This is not a question we can settle for you, because the answer is about where you intend to
use the thing. A filter you will pipe text through from a shell has to exist somewhere on your
machine: as a script you can run, or as a binary you have to build first, or as something you
install from a package registry. Those are different products, and picking wrong means either
you cannot run it or we build a toolchain nobody wanted.

## Question

What must this run as, and in what environment — that is, what do you want to be able to type at
a shell to use it, and what can we assume is already installed on the machine that types it?

## Options considered

- **A —** A single Python 3 script using only the standard library, run as `python3 mdtab.py` or
  as an executable `./mdtab`. Consequence: nothing to build and nothing to install as long as a
  Python 3 interpreter is present; tests run with `python3 -m unittest` with no dependencies; it
  is a text file you can read and edit. Startup is a few tens of milliseconds, which is
  invisible for a filter you invoke by hand.
- **B —** A Node.js script run as `node mdtab.js`, distributable through npm. Consequence:
  requires Node to be installed; gets you a route to `npx`/`npm install -g` if you want other
  people to use it; a test runner has to be chosen and, unless we use Node's built-in one, that
  means a dependency.
- **C —** A compiled binary in Go or Rust, run as `./mdtab`. Consequence: fastest to start and a
  single file to copy to any machine with no runtime at all, which matters if you will call it
  from an editor on every save; but it must be compiled before it can be run, so the project
  gains a toolchain and a build step, and you cannot edit it in place.
- **D —** Something else the above does not cover — for example it must be a shell function, or
  it must run inside a specific editor, or it must work on a machine where you cannot install
  anything. If so, please say what the constraint is; that is more useful to us than a language.
- **Recommendation:** Ours is **A**. The tool is small, its whole job is text manipulation, and a
  dependency-free script is the option that costs you least to run and least to change. We would
  pick B or C only if you told us something A cannot do. This is our preference, not a decision —
  choose against it freely.

## Answer

[human] It is me, at my own machine, piping a file through it from my editor before I commit —
so it has to be a thing I can just run, with no build step and nothing to install first. Your
first suggestion is right: a plain script that runs on what is already there. I have opinions
about languages but they are not worth much here, so take that decision yourselves.
