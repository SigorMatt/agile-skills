**[review-close, 2026-08-27, ending the engagement] A correction to this question's own
`## Context`.** The example command in the first bullet above is wrong, and it was wrong when the
stakeholder read it:

```
python3 -m expenses expense add --amount 30.00 --paid-by Ana --shared-by Ana --shared-by Ben ...
```

`--shared-by` takes **one comma-separated list**, not a repeated flag [src: expenses/cli.py;
README.md]. Repeating it is standard `argparse` last-wins, so that command records the dinner as
shared by **Ben alone** and silently produces the wrong arithmetic. The command that does what
the bullet claims is `--shared-by Ana,Ben`. Checked by running both forms against a scratch store
on 2026-08-27; the repeated form stored `"shared_by": ["Cleo"]` for a three-way dinner.

The original text above is left exactly as the stakeholder saw it — `question.md` §3 rule 6, a
question's record is not rewritten — and this note is the correction. Nothing else in the
question was wrong: `person add` and `settle` are as quoted, and the capability the bullet
describes does exist and is correctly documented in `README.md`. The defect is in this artifact,
not in the tool, and it did not affect the answer: the stakeholder refused over the missing CSV
import, which this note does not touch. Recorded as a finding in
`tracker/items/EP-001/artifacts/review.md`.
