## Context

This is intake for **EP-001**, the dice roller, round 1. There are three questions in this round
and this is the first; the third says so and is the last of them.

You said: *"A little command-line dice roller: I type something like `3d6+2`, it rolls and shows
the result and the breakdown. It should remember the rolls from the current session so I can see a
history. Python."*

Everything in that sentence is clear except one word, and it happens to be the word that decides
the shape of the whole thing: **session**. Two quite different programs both match what you wrote,
they are built differently, and the history means something different in each. We have written the
two work items (`WI-0001` rolling, `WI-0002` history) so that they survive either answer, but
neither can be made Ready until this is settled.

## Question

When you use this, are you typing expressions one after another at a prompt the tool keeps open —
so that "the current session" is one run of the program — or are you running a separate shell
command for each roll?

## Options considered

- **A — An interactive prompt.** You run `droll`, get a prompt, type `3d6+2`, see the result,
  type another, and type something like `history` to see them all; quitting ends the session.
  Consequence: the history lives in memory for as long as that run lasts and nothing is written to
  disk, which is the smallest thing that delivers everything you described.
- **B — One shell command per roll.** You type `droll 3d6+2` at your shell, get one result, and
  the command exits. Consequence: "the current session" can no longer mean the program's lifetime,
  because it has none — the history would have to be written somewhere on disk, and we would then
  need to decide where it lives and what clears it. That is real extra work and it contradicts your
  "current session" wording, so we would want you to confirm it rather than assume it.
- **C — Both.** `droll 3d6+2` for a single quick roll, and `droll` with no arguments for the
  prompt; only the prompt mode keeps a history. Consequence: two entry paths to build, document and
  test, for one product; roughly the work of A plus a third again.
- **Recommendation:** A. "Remember the rolls from the current session" reads most naturally as one
  run of the program, and A is the least machinery that does everything you asked for. But this
  decides what the product *is*, not how it is built, so we would rather be told than guess.

## Answer

Option **A**, the interactive prompt, chosen by the stakeholder in their own words:

> [human] A — the open prompt. I fire it up, keep typing rolls one after another, and close it when we're done for the night.

"The current session" therefore means one run of that prompt: the program is started once, reads
expressions until the user quits, and holds the history in memory for exactly that long. Nothing
is written to disk. This is the answer's own content, not a reading of it — no document was needed
and none was relied on.
