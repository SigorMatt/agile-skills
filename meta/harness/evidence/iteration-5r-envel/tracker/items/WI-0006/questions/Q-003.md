## Context

`WI-0006`, round 1, question 3 of 4. One conversation about a command that lists an envelope's
spends. **If you closed the item at question 1, ignore this one.**

This one is about whether you have to name an envelope.

The item as drafted says you do: `envel spends groceries`. That came from the phrase it was
derived from — you said you would put a description on the spends you might query later, and
querying a spend implies you know roughly where it is. But the case where you *do not* know is
real: you are checking a card statement against the tool, you find a 34.99 you cannot place, and
you do not know which of your eight or ten envelopes it came out of. Naming an envelope is
exactly what you cannot do.

Against that: you have told us twice that you want less listing rather than more, and a command
that prints every spend across every envelope is the closest thing this tool would have to the
spreadsheet you are leaving.

## Question

Should this command always require you to name an envelope, or should you also be able to ask
for the spends across all of them at once?

## Options considered

- **A — Always name an envelope.** `envel spends groceries`, and nothing else. Consequence: the
  output is always about one envelope and is always short; there is one way to type it. The cost
  is the statement case above — a spend whose envelope you have forgotten cannot be found except
  by running the command once per envelope.
- **B — The envelope is optional; leaving it out shows all of them.** `envel spends` shows
  every envelope's spends, each line saying which envelope it came from. Consequence: the
  statement case works, and it is one more optional argument rather than a new command. The cost
  is that the bare command is the long output — and, combined with question 2, `envel spends` on
  its own could be every spend you have ever recorded.
- **C — Always name an envelope, and let it be a word that matches several.**
  `envel spends gro` lists every envelope whose name starts with `gro`. Consequence: less typing
  for the common case. The cost is a matching rule you have to learn, and it does not solve the
  statement case either, since you still have to guess at the name.
- **D — Always name an envelope now; a search across all of them later if you find you need it.**
  Consequence: the smallest thing to build and it covers the case you described. The cost is
  that the statement case — the one you have told us you actually do, a couple of days after
  each month ends — is the case it does not cover.
- **Recommendation:** ours would be **B**, coupled with answering **B** at question 2 so that
  the bare `envel spends` means *this month, everything*, which is a readable amount of output
  and is exactly the view you would want with a statement in front of you. If the two together
  feel like more tool than you want, **A** is the smaller and entirely defensible answer.

## Answer

[human] B — let me leave the envelope out and see the lot. The case I actually have is a 34.99 on
the statement I cannot place, and that is precisely the moment I cannot name an envelope. One
month across ten envelopes is a page I can read; that is why I want the month on it.
