## Context

`WI-0006`, round 1, question 1 of 4. Four questions in all, and they are one conversation about

**This is the one item on the board you never asked for**, and this question is here to give you
a plain chance to close it. We derived it from a single phrase of yours, and we would rather be
told we over-read you than build it and find out later.

The phrase is from `WI-0002/Q-002`, where you chose to have an optional description on a spend:
*"B — optional. I'll put one on the ones I might query later and skip it on the weekly shop."*

You have that. `envel spend groceries 12.50 lunch` records `lunch` against the spend, and it is
in your file. What you cannot do is read it back. At `EP-001/Q-003` you were emphatic about the
monthly summary: *"I definitely don't want every individual spend listed — that is the
spreadsheet I am trying to get away from."* That was the only report in the tool, so today there
is no command anywhere that can show you one spend, let alone its description.

So one of two things is true, and only you know which:

- you meant you would want to look those spends up, in which case this item is what you meant
  and the description finally has a reader;
- or *"query"* was a loose word for something else — checking a figure against a statement, or
  just knowing the note is there — in which case this item is us inventing a requirement, and
  the honest thing is to close it.

One thing that is **not** a reason to say yes: `WI-0005`, correcting a spend. That item does
need a way to point at one spend, but it does not need this command — it could carry its own way
of naming a spend. We have asked you about that separately at `WI-0005/Q-001`, and if you answer
**A** there, this item becomes the natural place the reference is printed. Treat the two as
related but decide this one on its own merits.

The other three questions this round are about what this command would print if you want it:
which spends it covers, which envelopes, and whether it shows only spends or everything that
moved the envelope. **If you answer "close it" here, those three fall away — say so and ignore
them.**

## Question

item be closed as something we inferred and you did not mean?

## Options considered

- **A — Yes, build it.** Consequence: the description you chose at `WI-0002/Q-002` becomes
  readable, and you gain a way to check what is behind an envelope's balance without opening the
  data file. The cost is a piece of work you did not ask for, at the end of the queue, and one
  more command in a tool you wanted to be small.
- **B — Close it.** Consequence: nothing to build, and the epic finishes with the five items you
  did ask for. The cost is that the description stays a field nothing can read — you would be
  typing notes into a file only a text editor can show you — and if `WI-0005` needs a way to
  name a spend, it will have to invent one of its own.
- **C — Keep it on the board but not in this round.** Leave it at `draft`, unrefined, and see
  whether you miss it once you have been using the tool. Consequence: no work now, and the
  question stays visible rather than being decided in the dark. The cost is that the epic cannot
  finish while a child item is unresolved, so this would hold the ending open — and a `draft`
  item nobody has decided about is exactly the thing that rots on a board.
- **Recommendation:** ours would be **A**, and we hold it weakly, because the argument for it is
  yours and the argument against it is also yours. For: you chose an optional description over
  no description and over a compulsory one, and gave *"the ones I might query later"* as the
  reason — a field chosen for a purpose it cannot serve is an odd thing to leave. Against: you
  have twice told us you want less listing, not more, and you are the person who has to type one
  more command name. If you close it, we will record that as your decision and not as an
  oversight.
