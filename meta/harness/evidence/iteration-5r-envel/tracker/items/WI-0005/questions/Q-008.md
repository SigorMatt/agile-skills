At `WI-0005/Q-001` you asked for *"a short number I can read off and type back"*, and the example
in front of you was `envel spends groceries` printing a line beginning `7`. Read strictly, that is
a number counted **within** an envelope — `groceries` has a 7 and so does `fun`.

> [human] B — let me leave the envelope out and see the lot. The case I actually have is a 34.99
> on the statement I cannot place, and that is precisely the moment I cannot name an envelope.

That is the case where a per-envelope number stops working. The listing shows you a page of
entries across ten envelopes, you find the 34.99, and the number beside it is `7` — and there are
ten sevens on the page. You would have to type the envelope as well as the number, at the exact
moment you told us you cannot name the envelope.

This is a question about what you type, so it is not ours to settle quietly. The difference shows
up in every correction you ever make.

One thing that does **not** turn on it: nothing renumbers behind you. Whichever you choose, the
reference of an entry stays that entry's for good, so a number you wrote down last week still
means what it meant. Removing an entry does not shuffle the others.

## Question

Should the reference be numbered within each envelope — so `groceries 7` and `fun 7` are different
entries — or once across everything you have recorded, so a number on its own is never ambiguous?

## Options considered

- **A — One number across everything.** The first entry you ever record is `1`, the next `2`,
  whatever envelope it went into. `envel fix 148 --amount 14.00`. Consequence: a number on its own
  always means one entry, so the statement case works and a correction is one short line. The cost
  is that the numbers get long with use — after a year of a few entries a week you are reading
  three-figure numbers off the screen — and a number tells you nothing about which envelope it is
  in until you look at the line beside it.
- **B — A number within each envelope.** `groceries 7`, and you type
  `envel fix groceries 7 --amount 14.00`. Consequence: the numbers stay small for ever, and a
  reference carries the envelope with it, so a correction line says what it is about. The cost is
  the statement case: the envelope-less listing has to print the envelope beside every number, and
  you have to type both — at the moment you could not name the envelope, although by then the
  listing has told you.
- **C — A number within each envelope, and the listing prints it in one piece.** As B, but the
  reference is shown and typed as a single word, `groceries/7`, so you still copy one thing off
  the screen. Consequence: the numbers stay small, one thing to type, and the reference says which
  envelope it belongs to. The cost is a new bit of punctuation to learn, and an envelope whose
  name contains a `/` would need a rule — you asked at `WI-0001/Q-004` not to have the characters
  in a name restricted, so that rule would have to be ours to invent.
- **Recommendation:** ours would be **A**. The reason is the case you described yourself — the
  34.99 you cannot place — where the envelope is exactly the thing you do not know, and A is the
  only one of the three where what you type next does not contain it. Long numbers are the real
  cost and we think it is a small one: you read the number off the line you are looking at rather
  than remembering it. If you would rather the reference told you which envelope it belonged to,
  **C** is the better of the other two and we would take the `/` rule on ourselves.
