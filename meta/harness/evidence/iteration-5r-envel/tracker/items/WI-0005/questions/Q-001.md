## Question

When you want to correct a spend you recorded earlier, how do you want to point at *which*
spend it is?

## Options considered

- **A — The tool gives each spend a short number, and a command shows them.**
  `envel spends groceries` prints something like `7  2026-09-07  12.50  lunch`, and you then
  type `envel fix 7 14.00`. Consequence: it works however long ago the mistake was, and the
  number is unambiguous — you read it off the screen rather than remembering it. The costs are
  real: you have to run a second command first, this item then genuinely needs `WI-0006` (or
  something like it) built before it is usable, and the number has to keep meaning the same
  spend for ever, which constrains how the file is stored.
- **B — Describe the spend you mean: envelope, amount, and the date if you need it.**
  `envel fix groceries 125.00 12.50`, or `envel fix groceries 125.00 12.50 --on 2026-09-07` when
  one is not enough. Consequence: nothing new has to be built first and you type one command. The
  cost is the case where two spends match what you typed — the tool would have to refuse and tell
  you it found two, and you would need the date to separate them; if two spends of the same
  amount landed on the same day in the same envelope, there would be no way to say which.
- **C — Always the last spend in that envelope.** `envel fix groceries 12.50` changes the most
  recent spend recorded against `groceries`. Consequence: the shortest thing to type and nothing
  new to build, and it covers the mistake you notice the moment you hit return. It does nothing
  at all for a mistake you find when you check the month against your statement — which, from
  what you have told us about how you use this, is when you would find most of them.
- **D — The tool prints a reference when you record the spend, and you keep it.**
  `envel spend groceries 12.50 lunch` answers `spent 12.50 from groceries (ref 7), which now
  holds 87.50`. Consequence: no listing command is needed and the reference is unambiguous. The
  cost is that it only helps if the terminal is still on screen; a week later the number is gone
  and you are back to option B or C.
- **Recommendation:** ours would be **A**, and it is the most expensive of the four. Our reason
  is your own description of when you would catch a typo — *"a couple of days after it has
  ended"*, checking a month against a statement [src: EP-001/Q-004] — which is exactly the case
  C and D do not serve, and B serves only until two spends look alike. A also turns `WI-0006`
  from a thing we invented into a thing this item needs. This is our reading of your habits and
  not something you have told us; if you would rather have the cheap version now and the listing
  later, **B** is a smaller piece of work and we will build it.

## Answer

[human] A. I find these mistakes a couple of days after the month has ended with the statement in
front of me, so an option that only reaches the last spend, or a number that scrolled off the
screen a week ago, is no use to me. Give each spend a short number I can read off and type back.
That does mean the listing command has to exist, and I am saying yes to that separately.
