## Context

`WI-0001`, round 1, question 1 of 4: what happens when you create an envelope that already
exists. Four questions in all, and they are one conversation about the same item — the four
things nobody has said yet about setting up envelopes and putting money in them.

`WI-0001` AC1 says a command creates an envelope with a name you choose. It does not say what
happens when that name is already taken, and one of the plausible answers loses money that is
already in the envelope, so this is not ours to pick.

## Question

What should happen when I create an envelope with a name that already exists?

## Options considered

- **A — Refuse, and say it already exists.** Nothing changes, and the tool exits with an error.
  Consequence: an envelope's balance can never be destroyed by a mistyped create; the cost is
  that re-running a setup script fails on the second run.
- **B — Do nothing, and say it already exists.** The envelope is left exactly as it was and the
  tool exits successfully. Consequence: creating is safe to repeat, which makes a setup script
  or a shell-history recall harmless; the cost is that a genuine mistake — you thought you were
  making a new envelope — looks like success.
- **C — Reset it: the envelope is emptied and starts again at zero.** Consequence: a way to
  start a name over without deleting it. The cost is that one command with no warning destroys
  a balance, and `WI-0001` has no undo.
- **Recommendation:** ours would be A. Money already in an envelope is the thing this tool
  exists to keep, so the answer that cannot lose it silently is the safe default; if repeating a
  create turns out to be something you do often, B is a small change later.

## Answer

[human] A — refuse and tell me it already exists. I will be setting these up by hand, eight or ten of them, so the second run of a create is a mistake and I want to hear about it. Nothing should ever be able to wipe money out of an envelope by accident.

- `EP-001/Q-005` — compatible, and worth stating because it looks like a tension and is not.
  *"Nothing should ever be able to wipe money out of an envelope by accident"* sits beside a
  request to be able to **correct** a recorded entry, which does change a figure. The word doing
  the work is *accident*: a correction is a command they typed on purpose, aimed at one entry; a
  repeated create is a command they typed believing it would do something else. `WI-0005` is the
  deliberate route and this answer closes the accidental one.
- `WI-0001/Q-004` — compatible, and the two interlock: this answer refuses a duplicate name, and
  that one decides which names count as duplicates. `Groceries` when `groceries` exists is
  refused, and `WI-0001` AC7 and AC11 say so together.
