# Implementation report — WI-0003

## What was built

`envel summary`, a subcommand that prints one row per envelope for a calendar month, with four
labelled figures in the row: what went into the envelope that month, what was spent from it, the
net moved into or out of it, and what was left in it at the end of the month.

Three files changed and two are new:

- **`envel/dates.py`** gains `parse_month`, `this_month` and `month_of`, and a module constant
  `MONTH_LENGTH` so that the seven characters of a month are written once. `parse_month` carries
  the month range `01`–`12` in its own pattern, because there is no `date.fromisoformat` for a
  month to check the calendar afterwards the way `parse_date` does [src: ADR-0008].
- **`envel/summary.py`** (new) holds `entry_month`, `figures`, `row` and `summarise`
  [src: ADR-0009]. The month an entry falls in is its `on` if it has one and its `at` otherwise —
  one expression with no mention of `kind` [src: ADR-0008] — and every figure is a filtered sum
  over the entries naming the envelope.
- **`envel/cli.py`** gains the `summary` subparser, one optional positional `month` and no
  options, and one dispatch branch. `summary` joins the top-level `metavar`.
- **`tests/test_summary.py`** (new), 27 tests over the module as a function of (document, month).
- **`tests/test_dates.py`** gains a `Month` class; **`tests/test_cli.py`** gains a `Summary`
  class that runs the tool as a separate process against a scratch `ENVEL_FILE`.

Nothing this item does changes a stored byte: `summarise` returns `Ok` with `changed` at its
default of false, so `cli` never saves [src: envel/cli.py:140].

The arithmetic is what makes AC3's reconciliation hold, rather than any step arranging it. Every
entry has exactly one month and exactly one kind, so the three month-M columns partition month
M's entries; `left` is the sum over months up to and including M; so `left − (in − spent + moved)`
is the sum over months before M, which is the carried-in balance by definition. Nothing in
`envel/summary.py` computes a carried-in figure and nothing there checks the identity — the test
computes it independently and asserts it.

## Deviations from the plan

1. **The plan's steps were paired rather than executed one to ten in file order.** Step 7's tests
   were written and committed with step 1, step 8's with steps 2 to 5, and step 9's with step 6.
   The procedure requires the test to come with the change in the same commit, and the plan's
   ordering would have put four code steps on the branch untested. Nothing about *what* was built
   changed; the four commits on `main..wi/WI-0003` are the three pairs plus the document repair.
2. **`envel/dates.py` gained a module constant, `MONTH_LENGTH = 7`.** Step 1 asked for
   `month_of(text)` to be `text[:7]`, *"named so that the seven is written once"*. `this_month`
   also needs the seven, so the literal is now written once in a constant and used by both rather
   than appearing twice. Same behaviour, and the plan's reason is what asked for it.
3. **`envel/dates.py`'s module docstring was reworded.** It said *"These three functions are the
   only conversions…"* and there are now six, so the sentence had become false in the same commit
   that made it so. Rewritten as *"The functions here…"*, with a paragraph naming `ADR-0008` and
   what a month is. This is source, not `docs/`, so no invalidation row covers it; recorded here
   because it is a hunk that traces to no acceptance criterion and no plan step.
4. **The plan's "reading `today` twice" risk was considered and not closed.** `cli` defaults to
   `dates.this_month()` and `summarise` compares against `dates.this_month()`, so a run at exactly
   midnight on the first of a month could refuse the month it had just defaulted to. The plan said
   to close it *"only if `implement` finds it free"*: it is not free — closing it means giving
   `summarise` the current month as a parameter, and both the plan and `ADR-0009` name the
   signature `summarise(store, month)`. Changing an interface an ADR states is not this skill's to
   do, and the cost of the risk is one refused invocation that succeeds when retried.
5. **Two tests in `tests/test_cli.py` seed the store file directly.** Step 9 asked for the `Move`
   class's shape, which runs the tool as a separate process. Two criteria are about a month that
   has ended, and no command creates an envelope into the past, so `test_a_spend_is_counted_in_the_month_it_happened_in`
   and `test_income_is_counted_in_the_month_it_was_recorded` write a store whose envelope was
   created in 2020 and then use the real commands for everything else. The first drafts of both
   used `envel new` and failed against AC7 working exactly as specified — the envelope did not
   exist by the end of last month, so last month had no rows. The code was right and the tests
   were wrong; they were fixed, not the code.
6. **AC12 gets five forms end to end rather than three.** Step 9 said *"the three malformed months
   of AC12"*; the test runs all five the criterion names. More than the plan asked for, in the same
   shape.
