## Context

`WI-0002`, round 1, question 2 of 2 — the last of this round.

A spend recorded as "groceries, 42.30" tells you an amount and an envelope and nothing about
what it was. Whether the tool keeps a description changes what it can show you later: option C
of `EP-001/Q-003` — a monthly summary that lists the individual spends — is only worth having
if each spend says something about itself. It also decides whether recording a spend is one
short command or one command with something to think about.

## Question

Should a recorded spend carry a short description of what it was for?

## Options considered

- **A — No description.** A spend is an amount, an envelope and a date. Consequence: the
  quickest possible thing to type, and the envelope name is the only category you get; the cost
  is that a list of past spends is a column of numbers you cannot identify.
- **B — An optional description.** You can add one, and nothing breaks if you do not.
  Consequence: quick when you are in a hurry and useful when you are not; the cost is that your
  history ends up patchy, with some spends identifiable and some not.
- **C — A required description.** Consequence: every spend is identifiable later; the cost is
  friction on the command you will run most often, which is the thing most likely to stop you
  using the tool at all.
- **Recommendation:** ours would be B. It costs nothing when unused, and it is the only one of
  the three that leaves the door open to a summary that lists spends without making the common
  case slower.

## Answer

[human] B — optional. I'll put one on the ones I might query later and skip it on the weekly shop. Don't make me type something every time.

  `WI-0003`.

  answered "available, not required".
- `EP-001/Q-005` — compatible: whether a correction may change a description as well as an
  amount is an open point recorded on `WI-0005`, not a contradiction between the two answers.
