## Context

This is the only question filed on `BUG-0001` at its close, and it is not about the change, which
passed review on all six criteria. It is about **one citation in `docs/` that this item's own code
change made point at the wrong line** — and it is the second occurrence of a defect whose policy
was settled nine minutes before this item's branch was cut.

`ADR-0012` `## Consequences`, first paragraph, says:

> **Easy: the bug closes without any sum changing.** Both surfaces are the same filtered sum
> bounded by a month [src: envel/summary.py:68] [src: envel/summary.py:173], and neither is
> touched.

Both citations were correct when `plan` wrote them. At `main` (`51a0a62`),
`git show 51a0a62:envel/summary.py` line 173 is `def bounded_balance(store, name, within):` — the
bounded sum the sentence is about. On the branch head, `sed -n 173p envel/summary.py` is
`    if "description" in entry:`, a line inside `entry_line()`.

That is worse than a line that merely drifted. `entry_line()` renders the **signed transaction
figure**, which is the one figure `ADR-0012` `## Decision` 4 exists to say is *not* a balance:
*"Transaction figures keep their signs … a figure that answers how much does this hold is worded; a
figure that answers how much moved, and which way is signed."* So the citation now offers, as
evidence that both surfaces are a bounded balance, the line that renders the thing the ADR
distinguishes them from. `bounded_balance` is now at `envel/summary.py:196`.

The companion citation is **fine** and is not part of this question: `sed -n 68p envel/summary.py`
is still `    left = sum(entry["cents"] for entry in mine if entry_month(entry) <= month)`. It sits
above this change's first insertion, so it did not move.

`validate-workspace` cannot see this, and did not: the line exists, so the citation resolves.
`lint-claims --changed-since main` exits 0 for the same reason. Only a reader comparing the line
with the sentence can tell, which is why this is filed by hand.

**Why no invalidation-set entry caught it.** `ADR-0012` was written by **this item's own `plan`**,
from the design it records, so it is in no invalidation set — a set lists the documents a change
could make *false*, and a document the plan writes from that same change is not one of them. This
item's set has twelve rows naming both product documents and four ADRs; the ADR it does not name
is its own. That is the exact structural gap `WI-0005/Q-009` identified and predicted:
*"Every later item whose plan cites a line its own implementation then moves will land in the same
place."* It landed here, on the next item.

**The remedy is not a new decision.** `WI-0005/Q-009`'s answer settled the policy for this shape —
repair the citation in place, with a `provenance` row in an append-only `## Corrections` section, a
`## Change log` row, and a version bump — and grounded it in `spec/doc-header.md` §4b rather than in
a preference. Both of §4b's conditions hold here as they did there: the sentence's **assertion is
unchanged** (both surfaces *are* the same bounded sum, and this item's `verify` measured that
identity directly — `left − (in − spent + moved) == balance_before` in both months tested), and the
replacement citation resolves **and supports** (`sed -n 196p envel/summary.py` →
`def bounded_balance(store, name, within):`). No reader has to change any code to satisfy the new
text, which is §4b's line between a correction and a supersession, so `ADR-0012` is corrected
rather than superseded.

This is filed rather than repaired by me for two reasons, both structural. `review-close` may write
under `docs/` only for a correction **inside this item's invalidation set**, and `ADR-0012` is not
in it — which is the whole problem. And `ADR-0012` has no `## Corrections` section yet, so the
repair creates one; that is a document edit, and document edits are `answer-questions`'.

**Non-blocking: `BUG-0001` closes on it and nothing waits.** It is recorded in this item's
`review.md` `## Accepted gaps` as `question-filed: BUG-0001/Q-002`, which is what makes an
`answer-questions` execution actually fall due rather than leaving the obligation in prose.

## Question

Repair `ADR-0012` `## Consequences`' stale `[src: envel/summary.py:173]` to
`[src: envel/summary.py:196]`, under `WI-0005/Q-009`'s settled policy — a `provenance` row in a new
append-only `## Corrections` section, a `## Change log` row, and `version: 1 → 2`?

And the narrower judgement this item cannot make for itself: **should the same pass also re-resolve
the two `envel/summary.py:<line>` citations in closed items' artifacts**, or are they dated records
that `Q-009` has already decided to leave alone?

## Options considered

- **A — Repair `ADR-0012`'s citation only, with the `## Corrections` row, change-log row and
  version bump; leave every tracker artifact alone.** This is `Q-009`'s answer applied without
  extension. Consequence: the one live, standing clause in `docs/` is made true again and the ADR's
  own record says why the number moved; the dated records stay dated. `Q-009` already reasoned the
  second half explicitly — *"an implementation report is a statement about a moment, not a standing
  claim"* — and the two tracker occurrences this change shifted are of exactly that kind:
  `tracker/items/WI-0005/item.md:272`, which cites `envel/summary.py:144` for *"the number first on
  every line"* — at `main` that line is `entry["ref"],` inside `entry_line()`, and on the branch head
  it is a docstring line inside `entry_kind()`; and
  `tracker/items/WI-0006/artifacts/impl-report.md:344`, which cites `envel/summary.py:123` — at
  `main` a docstring line inside `summarise()`, on the branch head the closing `)` of that
  function's future-month refusal. Both belong to items that are `done`.
- **B — Repair `ADR-0012` and every shifted tracker citation too.** Consequence: every
  `path:line` in the workspace resolves to a supporting line on one day. It also makes every future
  code change owe a sweep of every closed item's artifacts, which is unbounded work and contradicts
  `Q-009`'s reasoning about dated statements. The cost is not the edit; it is the precedent.
- **C — Repair `ADR-0012` by replacing the line citation with a symbol citation**, e.g.
  `[src: envel/summary.py]` naming `bounded_balance` in words, so the sentence cannot go stale this
  way again. Consequence: this ADR stops being able to drift, at the cost of a citation a reader
  must search for. `Q-009` raised precisely this as the question its own answer *"does not
  settle"* — whether `path:line` is the right form for a claim about a statement that keeps
  moving — and recorded that the right place for it is the retrospective. Taking it here would
  settle a record-wide design question from one instance of it.
- **D — Leave it.** Consequence: a citation in a current `## Consequences` that resolves and does
  not support, in the ADR that governs the very distinction the wrong line straddles. `Q-009`
  refused this option in the identical case, on the workspace's own rule that a citation which does
  not resolve is the appearance of evidence and one that resolves to the wrong line is that failure
  with better camouflage. Nothing mechanical would surface it again.
- **Recommendation:** **A**, and the team's preference rather than a decided thing. It is the
  option `Q-009` already chose for this shape, and choosing differently now would mean two policies
  for one defect. On the second half of the question, `A`'s reading — dated records stay dated — is
  also `Q-009`'s, and this item has no ground to overturn it.

  Worth saying plainly for whoever answers: this is the **second** occurrence in two consecutive
  items, and the first one's answer predicted the second. `C` names the real fix and `Q-009` sent
  it to `retro` rather than settling it; if that is still the right venue, then what this question
  deserves is `A` plus a note that the pattern has now recurred, which is written here so `retro`
  finds it with a count rather than an anecdote.

## Answer

**Option A on both halves, and the record decides it rather than a preference.**

`ADR-0012` `## Consequences`' stale `[src: envel/summary.py:173]` is repaired in place to
`[src: envel/summary.py:196]`, with a `provenance` row in a new append-only `## Corrections`
section, a `## Change log` row, and `version: 1 → 2`. The two `envel/summary.py:<line>` citations in
closed items' artifacts are left alone.

**Why A and not a fresh judgement: this is `WI-0005/Q-009`'s answer applied, not re-decided.** That
answer settled the policy for this exact shape and grounded it in the spec rather than in taste, and
both of `spec/doc-header.md` §4b's conditions hold here as they did there
[src: toolkit: doc-header.md section 4b "add a citation to an existing sentence"]:

- **The assertion is unchanged.** `## Consequences` says both surfaces are the same filtered sum
  bounded by a month and neither is touched. That is still true: `figures()`, `bounded_balance()`,
  `balance_before()` and `balance_through()` are absent from the change's hunks, and `verify`
  measured the identity on a month that closed short rather than inferring it — `left − (in − spent
  + moved)` equals `balance_before` at both bounds, including where the carried-in figure is itself
  negative [src: tracker/items/BUG-0001/artifacts/verify-report.md].
- **The new citation resolves and supports.** `sed -n 196p envel/summary.py` →
  `def bounded_balance(store, name, within):` [src: envel/summary.py:196], which is the function the
  sentence is about.

And §4b's non-negotiable line is not crossed: no reader has to change any code to satisfy the new
text, so `ADR-0012` is **corrected**, not superseded, and the bump is 1 → 2 rather than a thirteenth
ADR.

**On the second half — the two tracker citations stay as they are,** and this is `Q-009`'s reasoning
rather than a new ruling: *"an implementation report is a statement about a moment, not a standing
claim"*, and a dated statement repaired is history rewritten. Both occurrences are of exactly that
kind and both belong to items that are `done`:

- `tracker/items/WI-0005/item.md:272` cites `envel/summary.py:144` for *"the number first on every
  line"*. At the time that line was `entry["ref"],` inside `entry_line()`; it is now a docstring line
  in `entry_kind()`. The claim it supports is still true of the tool — `envel entries` still prints
  the reference first, and `WI-0006` AC2's tests assert it — so nothing in `docs/` is wrong and the
  item's own description remains a record of what its author read.
- `tracker/items/WI-0006/artifacts/impl-report.md:344` cites `envel/summary.py:123`, then a docstring
  line inside `summarise()` and now the closing `)` of that function's future-month refusal. An
  implementation report is the most dated artifact in the workspace.

Taking **B** instead would make every future code change owe a sweep of every closed item's
artifacts. The cost is not the edits; it is the precedent, and `Q-009` declined it for that reason.

**What this answer does not settle, deliberately.** Option **C** — replacing `path:line` with a
symbol citation so this class of drift becomes impossible — is the right fix and it is **not** mine
to take here, for the same reason `Q-009` gave: it is a workspace-wide decision about the record's
citation grammar, and settling it from the second instance would be settling it from an anecdote.
What this answer adds is the count. The pattern has now cost **three** reviews in one engagement,
and `Q-009` predicted this occurrence in writing before it happened:

> Every later item whose plan cites a line its own implementation then moves will land in the same
> place.

`Q-009` sent C to the retrospective. That is still the right venue and `retro` now has two instances
and a prediction that came true, rather than one instance and a worry. This paragraph is written
here so that it finds them together.

**One thing worth recording about why no gate caught it.** `validate-workspace` and `lint-claims`
both exit 0 on a stale line citation, correctly — they check that a citation **resolves**, and it
did. What makes this instance sharper than `Q-009`'s is where it landed: line 173 became
`if "description" in entry:`, inside `entry_line()`, which renders the signed transaction figure that
`## Decision` 4 of this very ADR exists to distinguish from a balance. The citation did not merely
drift; it came to rest on the one line that contradicts the sentence it was supporting. No mechanical
check can see that, and `review-close` found it only by resolving all 35 `envel/*.py:<line>`
citations in `docs/` one at a time. I re-ran that sweep on `main` after the merge before answering:
35 citations, this one stale, every other resolving to a line that supports its sentence. Only
`envel/summary.py` citations could have newly gone stale, because `envel/summary.py` is the only
module in this change's diff.
