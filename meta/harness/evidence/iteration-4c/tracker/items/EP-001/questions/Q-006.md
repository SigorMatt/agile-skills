## Context

This is the **only** question in this round, and it is the last one of the engagement. Everything
you asked for has been built and merged, and nothing is left running: three work items, all
closed, no bug outstanding, no question open anywhere.

You said it like this: *"A flashcard tool: add cards, review due cards daily, simple spaced
repetition. Progress persists."* What that turned into, in the terms you used rather than ours:

- You can **write a card down** — a question on one side, the answer on the other — and it stays
  written down. Close the terminal, restart the machine, come back tomorrow: it is still there.
- Once a day you can **run a review**, and it shows you only the cards that are due for you right
  now, not the whole pile. It tells you how many are waiting **before** it shows you the first
  one, so a backlog announces its size instead of ambushing you card by card — which is what you
  chose when we put the tension to you (`EP-001/Q-005`): *"I'd rather see the honest number of
  cards waiting than have the tool quietly decide which ones I don't get to see today."*
- For each card it shows the front, waits for you to press Enter, then shows the back and asks
  whether you got it right. **Wrong brings it back tomorrow. Right pushes it out** — one day,
  then three, then seven, then thirty, and thirty thereafter.
- You can **stop part-way** by typing `q`, and every answer you had already given is kept. If the
  tool is killed outright at a prompt, the same is true: the cards you answered keep their new
  schedule, and the ones you never reached are untouched and still due.
- You can **throw a card away** by typing its front side. Before it goes, the tool shows you the
  card — both sides, the rung it had reached, when it was next due — and asks. That was your
  call: *"one keystroke is worth it to not lose a month of progress by fat-fingering a delete"*
  (`WI-0003/Q-002`). If two cards share that front side it lists them and asks which one.
- **Everything** — the cards and everything the tool has learned about how well you know each one
  — is in a single plain-text file on your own machine. No server, no account, nothing leaves the
  computer.

It is run from a terminal, which is what you chose knowing the alternatives (`EP-001/Q-001`):

```
python3 -m recall add "bonjour" "hello"
python3 -m recall review
python3 -m recall delete "bonjour"
```

**How much of it actually works, and how we know.** Ninety automated tests run against the tool
as a real command with real keystrokes, and they pass on the merged trunk. Each work item was
checked independently against its own written criteria by someone who ran the commands rather
than reading the developer's report — thirty-eight criteria in total, every one demonstrated. On
the last item we also broke the code nine different ways on purpose to confirm the tests would
notice; all nine turned the suite red.

**What we would want you to know before you answer**, because none of it is written anywhere you
would look:

- **Deleting is permanent.** No undo, no trash, no way to skip the confirmation prompt. That is
  the choice you made in `WI-0003/Q-002`, and we have built no back door to it.
- **The tool assumes it is the only thing writing the file.** If you somehow had two review
  sessions going at once, the second one to finish would overwrite the first. For one person on
  one machine this never comes up; we are telling you because we accepted it deliberately rather
  than missed it.
- **Nothing has been tested against a real reboot**, only against stopping and starting the tool.
  The file is an ordinary file on your disk, so we have no reason to expect trouble; we have not
  proved it.
- **You cannot edit a card**, only add and delete one. You said editing could wait
  (`EP-001/Q-004`), so it was never built.
- **There is no way to list or search your cards.** You said you did not need one — *"I don't
  need a numbered list for this"* (`WI-0003/Q-001`) — so we recorded that as a decision, not as
  something postponed. It does mean the only way to see a card is to review it or to open the
  file in a text editor.

Every success measure this epic was written against is met. The two that lean hardest on your own
judgement are the last two, so they are worth stating plainly: *"a person can delete a card they
no longer want, and it stops being offered"* — met, and demonstrated by running a review before
and after a deletion; and *"the whole of the data lives in a file on the person's own machine and
survives a reboot of it"* — met as to the file, with the reboot itself untested as noted above.
