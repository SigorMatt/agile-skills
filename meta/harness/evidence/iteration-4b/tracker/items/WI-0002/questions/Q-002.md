## Context

This is refinement for WI-0002, the daily review sitting, round 1, question 2 of 2. That is all
of them for this item.

When we split the work at intake we assumed that a card is due on the day you add it, so that a
deck you have just built is reviewable straight away. That assumption was never put to you. It
is written down as an assumption in two places — `ADR-0002` §3 records it and says in terms that
it is this refinement's job to confirm with you, and `docs/product/vision.md` lists it under
"What is still open".

It has also already been built. `recall add`, which shipped as WI-0001, writes each new card with
a next-review date of the day it was added. That is a reason to settle this now rather than in
three items' time, not a reason to stop asking: if you want it the other way we would rather
change one line and one criterion today.

This is blocking, because it decides what happens on the one sequence you are most likely to
perform on day one — add some cards, then run a sitting — and WI-0002 cannot state that
behaviour without you.

## Question

If you add a card this morning, should it turn up in this evening's review sitting, or should it
first appear tomorrow?

## Options considered

- **A — It turns up today.** A card added today is due today, so a sitting later the same day
  includes it. Consequence: a brand-new deck is usable the moment you have typed cards into it,
  and you can test yourself on something immediately after entering it. The cost is that on a day
  you sit down and add twenty cards, that evening's sitting also contains those twenty on top of
  whatever else was due — the day you build the deck is the longest day. This is what the tool
  already does.
- **B — It first appears tomorrow.** A card added today is due the next day. Consequence: adding
  cards and reviewing cards stay separate activities, the day you build the deck stays short, and
  a sitting is only ever about recalling things rather than about seeing them for the first time.
  The cost is that a new deck shows nothing on the day you make it — `recall review` immediately
  after `recall add` would say nothing is due, which reads as broken if you were not expecting
  it — and it is a change to behaviour already delivered.
- **Recommendation:** ours is **A**, on three grounds: it is what you get today, adding a card
  and immediately checking you can recall it is a natural thing to do, and a first sighting on
  the day of entry is itself a review. We put it to you anyway because the cost of A is entirely
  yours — it is your evening that gets longer on the day you add a batch — and that is not
  something we can weigh for you. If you pick **B** we will change `recall add` and say so in the
  record.

## Answer

[human] Today — A. If I've just added a card I want to try recalling it right away, not wait till tomorrow.
