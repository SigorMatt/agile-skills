## Context

You accepted this engagement two messages ago:

> "A — accept as complete. This is what I asked for." (`EP-001/Q-004`)

We were about to close it. Before doing that we re-read what we had told you in the question you
were answering, checking each statement against the code rather than against our own documents —
and one of them is false. You should have the correction before we treat your acceptance as
final.

This is the only question in this round, and there is one thing wrong, not several.

**What we told you.** `Q-004`'s description of the tool opened with this:

> Your deck lives in a single file under your home directory
> (`~/.local/share/recall/deck.json` unless you set `RECALL_DECK`), which survives the process
> ending and a reboot.

**What is actually true.** Everything in that sentence except the four words in brackets. Your
deck is one file at `~/.local/share/recall/deck.json`, and it survives the process ending and a
reboot. But **there is no `RECALL_DECK`**, and there is no other way to point `recall` at a
different file — no environment variable, no command-line flag, no configuration file. The deck's
location is fixed. Setting `RECALL_DECK` to something would do nothing at all: `recall` would not
read it, would not warn you, and would carry on using the file above.

**How wrong it was, and how far it spread.** Not far, which is the one good thing here. The
mistake is in that sentence and nowhere else. The tool does what the rest of the record says it
does, and every document has always said the opposite of that parenthesis — the very next
sentence of `Q-004` pointed you at `docs/process/using-recall.md`, which says, under "Where the
deck is kept": *"Its location is fixed: there is no flag, no environment variable and no
configuration file for pointing `recall` at a different deck."* So no code is wrong, no
acceptance criterion is affected, and nothing else you were told at sign-off is untrue; we
checked the rest of that description line by line against the code and it all holds.

**Why we are stopping for it rather than noting it and closing.** Because of what you said would
make this tool a failure:

> "don't lose my progress — that's the one thing that would make this a failure"
> (`EP-001/Q-001`)

If you had believed that sentence, set `RECALL_DECK` to a folder you back up or sync, and worked
in the deck you thought you had told `recall` about, you would have found `recall` reading a
different file — which is exactly that failure, caused by us telling you something untrue. We do
not think that is likely; relocating the deck is not something you ever asked for, and
`ADR-0004` ruled it out at the time. But an acceptance is only worth what the description behind
it was worth, and deciding for you that this particular error does not matter is not ours to do.
