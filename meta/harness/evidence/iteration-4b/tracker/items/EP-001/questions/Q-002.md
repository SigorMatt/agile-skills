## Question

How do you want to operate this tool — what happens when you sit down to add a card or do
today's review?

## Options considered

- **A — A command-line tool.** You type something like `recall add` and `recall review` in a
  terminal, answer prompts, and it exits. Consequence: fastest to build and to check; every
  acceptance criterion becomes a command with an exit code, which makes verification
  unambiguous. It only works where you have a terminal, and the review session is a series of
  prompts rather than a screen.
- **B — A local web app you open in a browser.** A page on your own machine, with the deck and
  the review session as screens. Consequence: nicer to use daily and easier to extend later;
  costs a server process, a front end, and a way to start it, and acceptance criteria become
  harder to check without browser automation. Roughly doubles the work in each item.
- **C — A full-screen terminal application.** Runs in the terminal but paints a screen rather
  than scrolling prompts — you move through the review with single keypresses. Consequence: the
  daily-review experience of B without a browser, but the hardest of the three to verify
  automatically, and it needs a terminal-UI library.
- **Recommendation:** ours is **A**, because the whole value of the tool is in what it
  remembers rather than in how it looks, and A is the option where "the tool showed exactly the
  due cards" can be checked by a person with a terminal and no context. If daily use in a
  browser matters to you, say so — it is a real difference and B is a legitimate answer, not a
  worse one.

## Answer

[human] A command-line tool — I'm doing this at a terminal once a day, so option A works fine.
