## Context

AC2 requires the list of people to survive the process exiting, and EP-001 SM2 requires the same
of the whole tool. EP-001's scope says the data lives "in a file inside the project or the user's
home directory" and stops there.

The file's *format* is not being asked about here — that is a design decision and `plan` will
make it. Two things about it are yours, though:

- **Where it sits.** You are the one who has to know what to back up, and what to delete if you
  want to start the group's ledger over.
- **Whether one run can be pointed somewhere else.** This sounds like a detail and is not. EP-001
  SM1 and every acceptance check in this epic start "from an empty data store". If the location
  is fixed, then checking that the tool works means running it over your real data — so either
  the checks stop being run, or your ledger gets scribbled on. The same mechanism is what would
  let you keep one file per trip by hand.

## Question

Where should the data file live by default, and should a single run be able to use a different
file?

## Options considered

- **A — fixed at `~/.expenses.json`, no way to override it.** Consequence: nothing to remember
  and nothing to document. Every check of the tool's behaviour runs against your real ledger, and
  there is no way to keep a second group's expenses apart even manually.
- **B — `~/.expenses.json` by default, overridable for one run with `--data-file <path>`.**
  Consequence: same default, and the same nothing-to-remember for normal use. Checks and
  experiments run against a scratch file, and a separate trip can have a separate file if you
  ever want one. Costs one line in the documentation and one option on every command.
- **C — a file in the current directory, `./expenses.json`.** Consequence: natural if you keep a
  folder per trip, because the data belongs to wherever you are. Surprising the first time you
  run the tool from your home directory and it reports an empty group; and the report you get
  then depends on where you were standing, which is a hard bug to recognise.
- **Recommendation:** B. The default is the one you would pick anyway, and the override is what
  makes the tool checkable without touching your own data. Note that if you pick A, `verify` will
  have to record that SM1 cannot be checked from an empty store without deleting your file — that
  is a real cost, not a technicality.

## Answer

[human] A file on my laptop is fine — I don't want a server, an account, or anything in the cloud. The exact location and whether you can point it elsewhere for a run is your call.

**Read as a product answer plus a delegation. Route: recorded intent for the product half, decided
for the mechanics, recorded as
`docs/architecture/adr/ADR-0004-data-file-in-the-home-directory-overridable-per-run.md`.**

The stakeholder answered the part that was theirs: *"A file on my laptop is fine — I don't want a
server, an account, or anything in the cloud."* That confirms what `docs/product/vision.md`
already said and closes off any hosted or synchronised alternative. "The exact location and
whether you can point it elsewhere for a run is your call" hands back the rest, so `answered-by`
is `answer-questions`.

**The decision — option B.** The default data file is `~/.expenses.json`, resolved at run time
from the user's home directory. `--data-file PATH` overrides it for a single invocation, is
accepted by every subcommand, and is remembered by nothing. A file that does not exist is an
empty store rather than an error; the first command that records something creates it.

**Why the override is not a nicety.** Every success measure in EP-001 begins "from an empty data
store", and `verify` has to run real commands to check them. With option A's single fixed path,
checking the tool means writing to the stakeholder's own ledger — so either the checks stop
happening or the ledger gets scribbled on. There is no third option that keeps one fixed path,
which is why B is chosen over A even though A is simpler. C was rejected because a report that
depends on which directory you are standing in fails in a way that looks like data loss.

**One thing deliberately left open.** The file's *format* is `plan`'s, as the question said. The
`.json` in the default name anticipates the obvious choice without fixing it: if `plan` picks
another format it changes the extension and amends ADR-0004, which costs nothing while no data
exists. For that reason AC7 states the default and the override without quoting the filename, so
`plan`'s choice cannot invalidate a criterion.
