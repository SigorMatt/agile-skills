## Context

AC3 says that adding a name which is already registered must not create a second entry. Nothing
anywhere says what "already registered" means when the spelling differs, and WI-0001's own story
says the item exists so that "a typo does not silently create a fourth person" — which is
precisely the case that is unspecified.

The realistic failures are ordinary. You type `ana` on Tuesday and `Ana` on Friday. You paste
` Ana ` out of a chat message with a trailing space. If those are three different people, the
report splits one friend three ways and the arithmetic is wrong in a way that is hard to notice
and — because this epic has no way to edit or delete a person — impossible to clean up.

There is a second half to this. WI-0004 AC6 takes the sharers of an imported expense as a
comma-separated list (`--shared-by Ana,Ben,Cass`), so a name containing a comma could not be
named there. And a name that is empty, or only spaces, produces a person nobody can refer to at
all.

## Question

When should two spellings count as the same person, and which names should the tool refuse to
register outright?

## Options considered

- **A — exact match, and refuse only an empty or whitespace-only name.** Consequence: the
  simplest rule to state and to check. `ana` and `Ana` become two people, so the first typo
  creates the fourth friend this item is meant to prevent, and nothing can undo it.
- **B — trim surrounding spaces and compare case-insensitively; store the name as you first
  typed it; refuse a name that is empty, only spaces, or contains a comma.** Consequence: `ana`,
  `Ana` and ` Ana ` are one person, displayed the way you first wrote it. Refusing commas keeps
  `--shared-by` unambiguous for WI-0004, at the price of refusing a name like `Smith, Jr`.
- **C — as B, but also collapse runs of internal spaces and ignore accents, so `José` and `Jose`
  are the same person.** Consequence: catches more genuine duplicates. It also merges two people
  who really do spell their names differently, and that merge is unrecoverable for the same
  reason as above.
- **Recommendation:** B. It fixes the failures that actually happen — case and stray spaces —
  without silently merging people who are distinct, and the comma rule closes a hole in WI-0004
  before anything is built on it. If commas in names matter to you, say so and we make
  `--shared-by` take a repeatable option instead.

## Answer

[human] Use your judgement on the exact rule — just make sure a typo like "ana" vs "Ana" doesn't quietly create a second person.

**Read as a constraint plus a delegation. Route: decided within the stakeholder's constraint,
recorded as `docs/architecture/adr/ADR-0003-person-identity-trimmed-case-insensitive.md`.**

The stakeholder did settle one thing, and it is binding: *"just make sure a typo like 'ana' vs
'Ana' doesn't quietly create a second person."* That eliminates option A outright — not as a
judgement call by the architect, but by their instruction. The rest of the rule they handed back,
so `answered-by` is `answer-questions`.

**The decision — option B.** Two names denote the same person when they are equal after stripping
surrounding whitespace and case-folding. The name is stored and displayed exactly as first typed
(minus that surrounding whitespace), so `Ana` entered first and ` ana ` entered second is one
person, shown as `Ana`, and the second attempt is refused. A name that is empty, whitespace-only,
or contains a comma is refused outright, the comma because WI-0004 AC6 takes the sharers as a
comma-separated list and a name containing one could never be named there.

**Why not C.** C folds accents and collapses internal spacing, catching `José` and `Jose` as one
person. It also merges two people who genuinely spell their names differently — and EP-001
excludes editing and deleting, so that merge can never be undone, and every expense that named
either spelling is silently wrong afterwards. B fixes the failures that actually happen (case,
stray spaces) and refuses to make the ones that cannot be repaired. The asymmetry, not the
frequency, is what decides it.

**The cost, stated plainly.** A name like `Smith, Jr` cannot be registered. If that matters, the
recorded alternative is to make `--shared-by` a repeatable option and drop the comma refusal;
ADR-0003 says so, and it is a change to one item's argument parsing rather than to stored data.
