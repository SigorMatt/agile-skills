## Context

WI-0004 is `done` and merged, so every child of EP-001 is closed and this is the moment the epic's
own Definition of Done is applied (`spec/dor-dod.md` §4). Eleven of its twelve points are
straightforward. **DE4 — "`docs/product/` reflects what was actually built, not what was
proposed" — is not yet true**, and `review-close` may not fix it: `spec/doc-header.md` §5 assigns
`product/vision.md` to `intake`, `refine` and `answer-questions`, and this skill is not among them.

`docs/product/vision.md` is at v11. Its record of the **decision** is current and correct: v11 was
written when Q-006 was answered and it says, in the stakeholder's own words, that the import takes
the file's shape from them at each import and that the CSV sample no longer blocks anything. Nothing
there is wrong.

What is out of date is the description of the tool a reader would build a mental model from. Two
passages, both in `## How it is used`, still describe the command surface as it stood before
WI-0004:

1. **The command list.** *"One executable file named `expenses` … run as `./expenses add-person
   Ana`, `./expenses list-people`, and so on"*. Written when there were two commands; there are now
   six, and the sixth is the one the stakeholder refused to sign off a version without. A reader
   learns from this section that the tool registers people and lists them, and would not learn that
   it imports a bank statement — which is the epic's headline capability.
2. **The output rule.** *"Every command confirms what it did on stdout and exits 0; a refusal — a
   duplicate name, an unknown person — goes to stderr, exits 1, and changes nothing."* WI-0004 AC4
   adds a third case this does not cover: an import that could not use some rows prints
   `Skipped line <n>: <the row>` on **stderr** and still exits **0**, because the import as a whole
   succeeded. ADR-0005's own consequences flagged this as the case needing care, and it is now real
   behaviour. As written, the sentence is not false — a skip report is neither a confirmation nor a
   refusal — but a reader applying the rule to `import-csv` would draw the wrong conclusion from a
   non-zero-looking stderr.

Neither is a defect in the code, and neither blocks anyone: WI-0004 is delivered and merged, and
`README.md` documents all of this correctly for the user. The only thing gated by this is EP-001's
own closure, which is why the question is **non-blocking** and why the epic has been left `open` for
one more pass rather than closed with the gap noted.

Read for this: `docs/product/vision.md` v11 (all of it), `tracker/items/EP-001/item.md` SM3 and
`## Scope`, `tracker/items/WI-0004/item.md` AC1, AC4, AC6, AC10, `docs/architecture/overview.md` v5,
ADR-0005, and `README.md`'s new `### Importing from your bank` section, which already says the right
things and can be drawn on.

## Question

Update `docs/product/vision.md` so that `## How it is used` describes the tool as delivered: name
`import-csv` among the commands with the fact that the four column options are stated at every
import, and extend the output-and-exit-code rule to cover a partial import, which reports skipped
rows on stderr and still exits 0. Should anything else in `docs/product/` change at the same time to
satisfy DE4, or is that the whole of it?

## Options considered

- **A — amend `## How it is used` only, and bump to v12.** Add `import-csv` to the sentence listing
  the commands, with one clause on the per-import column mapping and why it exists (the stakeholder
  chose it in Q-006 rather than wait for a sample); and add the skipped-row case to the output rule
  as a third outcome beside confirmation and refusal. Consequence: DE4 becomes true with the
  smallest edit that makes it true, and the change log records what moved. **Recommended.** The rest
  of the document was updated as each decision was taken — eleven versions, one per decision — so
  the only thing lagging is the description of the surface, which no single decision owned.
- **B — A, plus a short section describing what the epic delivered end to end**, so that a reader
  arriving at `vision.md` after closure sees the finished shape in one place rather than
  reconstructing it from eleven change-log rows. Consequence: more to write and more to keep true
  later, and it duplicates `README.md`, which already does this for the user. Worth doing only if
  `vision.md` is meant to be read by someone who will not open the README.
- **C — decide DE4 is already met and close the epic without touching anything.** Defensible on the
  letter: nothing in `docs/product/` is *false*, and v11 does record the decision. Consequence: the
  epic closes a pass sooner, and `## How it is used` keeps describing a two-command tool.
  `review-close` declined this: WI-0004 was itself rejected one transition earlier for documentation
  that did not match what shipped, and certifying DE4 over the same class of gap immediately
  afterwards would empty the criterion of meaning. Recorded because it is a legitimate reading and
  the architect may take it.
- **Recommendation: A.** Smallest edit that makes DE4 true, no duplication of the README, and it
  keeps `vision.md` doing the job it has done for eleven versions — recording what the stakeholder
  decided and what the product therefore is.

One thing this question deliberately does **not** ask: whether the stakeholder's still-promised CSV
sample changes anything here. It does not. When it arrives it buys a named shortcut for the four
options, which `WI-0004/item.md` and `overview.md` v5 both record as a **new item**, and
`vision.md` v11 already says so.

## Answer

**Option A, and it turned out to be more than A.** `docs/product/vision.md` is at **v12**. This is
route 1 of the preference order rather than an architect's decision: nothing here needed deciding,
because the delivered behaviour is already recorded — `tracker/items/WI-0004/item.md` AC1, AC4, AC6
and AC10, `docs/architecture/overview.md` v5, ADR-0005's consequences note, and `README.md`'s
`### Importing from your bank` section. The document was simply behind them, and catching it up is
this skill's job under `spec/doc-header.md` §5.

Both passages the question named are fixed:

1. **The command list.** `## How it is used` now names all six subcommands, and gives `import-csv`
   its own paragraph — the tool holds no bank's format, so each import states its own file's shape,
   which the stakeholder chose in Q-006 (*"build it against the columns I name now… Typing four
   options each time is fine"*) rather than being a convenience someone picked. It also records
   that the still-promised sample buys a **new item**, not a change to this one, so a reader does
   not expect the surface to move when it arrives.
2. **The output rule.** The refusal clause now includes a file that has already been imported, and
   a new sentence covers the third outcome: a row the tool cannot use is named on **stderr** by its
   line number and skipped, the rest of the file is still imported, and the command exits **0**,
   because the import as a whole succeeded. ADR-0005's own consequences flagged that case as the
   one needing care, and the sentence cites it.

**And three more stale claims were found and fixed, which the question did not ask about.** The
question was scoped to `## How it is used`; the document was read end to end anyway, because DE6
exists precisely for prose nobody re-checks and the epic's own evidence is that this document had
been amended eleven times without anyone re-reading the parts no amendment touched:

- `## How we will know it works` still described SM3 as "a real bank CSV export populates it
  without hand typing". SM3 itself was rewritten in `tracker/items/EP-001/item.md` when Q-006 was
  answered, because a success measure that depends on a file only the stakeholder has is not
  checkable by anyone else. The summary now matches the measure, and says all four are met.
- The section heading **"Open at the time of writing"** and its opening line "All but one are now
  settled" were true from the moment the CSV sample became the last outstanding thing, and false
  from the moment Q-006 was answered. The heading is now "Questions put to the stakeholder, and
  where their answers landed", and it says plainly that nothing is open.
- Its counts were wrong in both directions: "Five questions at intake and four more by refinement".
  The real figures, from the files, are **five from `intake` and eleven from `refine`, sixteen in
  all**, every one answered — and six of the eleven were about one thing, the CSV sample.
  **WI-0004/Q-005 had no entry at all**; it now has one, because it is the asking whose failure is
  the reason Q-006 asked something else.

Option B was declined: a section describing the finished product end to end would duplicate
`README.md`, which already does that job for the reader who wants it, and would be a second copy to
keep true. Option C — declaring DE4 already met — was the reading `review-close` explicitly declined
and this answer agrees: the fix took one document and one version, and certifying a criterion over a
gap that cheap to close would have cost the criterion its meaning.

## Consequences

- `docs/product/vision.md` — v11 → **v12**, with a change-log row. Four changes: `## How it is used`
  now names all six commands and explains `import-csv`'s per-import column mapping and why the
  stakeholder chose it; the output-and-exit-code paragraph gains the already-imported refusal and
  the skipped-row case that exits 0; `## How we will know it works` matches SM3's rewritten wording
  and records that all four measures are met; and `## Open at the time of writing` is now
  `## Questions put to the stakeholder, and where their answers landed`, with corrected counts, the
  statement that nothing is open, and a new entry for WI-0004/Q-005.
- `tracker/items/EP-001/journal.md` — this execution, and what it found beyond what was asked.
- No item, plan or acceptance criterion changed. Nothing about the delivered behaviour was in
  question here: the code, the tests and the criteria are as `review-close` merged them, and this
  answer moved only the document that had fallen behind them.
- No ADR was written, and none was needed. Nothing was decided: every fact written into v12 was
  read from `WI-0004/item.md`, `overview.md` v5, ADR-0005 or the stakeholder's own words in Q-006.
