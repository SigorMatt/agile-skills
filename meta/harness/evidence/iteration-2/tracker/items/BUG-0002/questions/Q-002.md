## Question

ADR-0007 states as fact that `apply_plan` is imported only by `cli.py`, which `tests/test_apply.py`
contradicts. Given that an ADR is never edited to change its decision, how should the record be
corrected — is this within the "clerical correction" latitude of a version bump, or does it stand
as written with the correction recorded elsewhere?

## Options considered

- **A — correct the clause and bump ADR-0007 to v2, with a change-log row saying what was wrong.**
  The decision is untouched; only a supporting sentence about the code changes, to something like
  "the only production caller is `cli.py`; `tests/test_apply.py` also imports it and reads the
  type". Cost: two lines and a change-log row. Consequence: the ADR stops asserting something
  false, and the change log says so, which is the audit trail `spec/doc-header.md` §3 asks for.
  Risk: §4's "an ADR is never edited" is about the *decision*, and a reader could read this edit
  as broader licence than it is — the change-log row is what bounds it.
- **B — supersede ADR-0007 with an ADR-0008 that repeats the decision with the sentence fixed.**
  Cost: a whole new ADR, and every citation of ADR-0007 in `overview.md`, `plan.md`, `apply.py`
  and `cli.py` now points at a superseded record. Consequence: the letter of §4 is followed with
  nothing gained — the decision never changed, so there is nothing for a new ADR to decide.
- **C — leave ADR-0007 as written, and record the correction in `overview.md` instead**, where
  the same fact can be stated truly and which §5 lets you edit. Cost: one sentence, in the edit
  Q-001 already asks for. Consequence: the false sentence stays in a `status: current` ADR, and
  the next reader who follows a citation to ADR-0007 — rather than to the overview — still gets
  it. This is the propagation path `spec/doc-header.md` §4a was written about.
- **Recommendation: A.** The decision is sound and unchanged; what is wrong is a factual claim
  about the code, made in the one paragraph a later `plan` will read to judge whether reversing
  this is cheap. Fixing it in place with a change-log row is the smallest thing that leaves every
  citation of ADR-0007 pointing at something true.

## Answer

**Option A: the clause is corrected and ADR-0007 goes to v2, with a change-log row saying what was
wrong.** Answered from the record; no escalation, and none of the four conditions in
`spec/question.md` §4 applies — the decision is not being changed, nothing irreversible is being
committed, no ADR is being contradicted, and the record is not silent.

What settles it is the scope of the rule the question worries about. `spec/doc-header.md` §4 says
an ADR "is **never edited to change its decision**", and that it "is superseded by a new ADR" —
both clauses are about the **decision**. The same spec's §3 then requires that *every* content
change to *every* document under `docs/` bump the version and add a change-log row, and says in
terms that "fixing a typo is a content change. The rule has no exceptions". A document class that
could never be edited would have no use for that rule. So an ADR may be corrected on a matter of
fact, and the mechanism that keeps the correction honest is the change-log row, which is now
there and names exactly what was wrong.

Option B is what §4 asks for when a decision moves, and nothing here moves one: ADR-0007 still
decides the tagged `Outcome`, still assigns the exit status to `kind`, and its reversibility
verdict — cheap — is still right. An ADR-0008 that repeated all of that to fix one clause would
point every existing citation of ADR-0007 at a superseded record for no gain. Option C leaves a
`status: current` ADR asserting something false about the code, which is the propagation path
`spec/doc-header.md` §4a was written about; correcting it elsewhere does not help the reader who
follows a citation *to* ADR-0007.

**Two occurrences, not one.** The review quoted the reversibility paragraph. The same section's
`What becomes hard` paragraph says "There is one caller [src: tidy/cli.py]", which is wrong in the
same way — `tests/test_apply.py` calls `apply_plan` directly. Fixing only the sentence that was
quoted would have left the false claim in the document one paragraph up, so both were corrected in
this edit.

The review is right that the ADR contradicted itself: Option A, two sections earlier, already
costed "the two existing assertions that index into the returned list must read `.message`". The
corrected text now points at that, so the two paragraphs agree.
