## Context

This is question 3 of 4 on EP-001, part of the same intake ask as Q-001; see that file for the
frame.

You said "organises a messy folder". A messy folder usually contains some subfolders as well as
loose files, and intake cannot tell from your words whether those subfolders are things to be
tidied *into* or things to be tidied. Intake has provisionally written "recursion into subfolders"
into the epic's out-of-scope list, but that is a placeholder for your answer, not a decision.

This is intent that no document records, and it changes what "done" means for every item: it
decides what the tool's very first step — listing what is there — actually returns, and it decides
whether a second run over an already-tidied folder is safe or re-sorts the subfolders the first run
created.

## Question

When the tool is pointed at a folder, does it organise only the loose files sitting directly in
that folder, or does it also descend into the subfolders that are already there?

## Options considered

- **A — Top level only.** Only files sitting directly in the target folder are considered;
  existing subfolders are left completely alone and are never entered. Consequence: running the
  tool twice is safe and idempotent, because the folders it created on the first run are ignored
  on the second. Cost: nested mess stays messy.
- **B — Descend into everything**, tidying files at any depth into subfolders at the top level.
  Consequence: a genuinely nested mess gets flattened and sorted in one pass. Cost: the second run
  re-processes the folders the first run created, so the tool must be able to recognise and skip
  its own output, and it will pull apart folders you had deliberately organised yourself.
- **C — Top level only by default, with descending available on request.** Consequence: safe
  default, escape hatch when you want it. Cost: two behaviours to specify, test and preview, so
  it is more work than A and inherits B's problems in the non-default case.
- **Recommendation:** A. It is the safest default, it is idempotent, and it never touches a folder
  you organised yourself. C is the natural follow-up once A is delivered and would be a fourth
  work item rather than a change to the three that exist.

## Answer

[human] Top level only — leave existing subfolders alone. Simplest option, go with that.

Recorded as given: **option A — top level only.** Only files sitting directly in the target folder
are considered; existing subfolders are neither entered nor moved.

Two consequences the option list drew out are now written down as criteria rather than left
implicit: a subfolder and everything in it must be unchanged by a run, and a second real run must
therefore be a no-op, because the folders the first run created are subfolders on the second.
Filed as WI-0001 AC9 and AC10; `refine` renumbered them to **AC11** and **AC12** when it rewrote
the criteria at 2026-08-27T15:58:15Z, and those are the current numbers. Descending on request remains a possible fourth work item and is not
being built.
