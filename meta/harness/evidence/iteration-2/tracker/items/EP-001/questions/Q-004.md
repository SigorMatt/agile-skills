## Question

After WI-0001, which should be built next — WI-0002 (routing by age) or WI-0003 (your own rules)?

## Options considered

- **A — WI-0002 next, then WI-0003.** Consequence: the tool does everything you originally
  described (type *and* age) as early as possible, and the rule format that WI-0003 then designs
  can cover both type and age from the start, because both exist by then. Cost: you cannot change
  any rule yourself until all three are done.
- **B — WI-0003 next, then WI-0002.** Consequence: you get control over the rules sooner, so you
  can start using the tool on your own folder with your own type mapping before age handling
  exists. Cost: the rule format is designed for type-only rules and then has to be extended for
  age, which usually means changing it twice.
- **C — Neither is more important; whichever is easier.** Consequence: intake records both at the
  same priority and the pipeline takes them in ID order (WI-0002, then WI-0003), which is A by
  another route. This is a legitimate answer if you genuinely do not mind — say so and we will
  record it as your decision rather than as our guess.
- **Recommendation:** A. It finishes the behaviour you actually asked for first, and it avoids
  designing the rule format before we know everything it has to express.

## Answer

[human] Doesn't matter to me, honestly — whichever's easier for you. Just don't leave either one
hanging forever.

**Decided by the architect under that delegation** (`answer-questions`, 2026-08-27): **WI-0001,
then WI-0002, then WI-0003** — option A, reached by the route option C describes. The reason for
putting WI-0002 first is the one option A gave: by the time WI-0003 designs a rule format, both
type and age exist, so the format is designed once for everything it has to express rather than
extended a second time.

"Just don't leave either one hanging forever" is recorded as a constraint on the ending, not only

drop it.
