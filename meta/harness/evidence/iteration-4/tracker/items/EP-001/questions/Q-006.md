`recall delete` acts at once and tells you what it removed, which is what you asked for
(*"just delete it and tell me what got deleted… I don't need a prompt in my way for that"*). It
takes the number `recall list` prints. A number that names no card is refused and nothing is
touched. Deleting is final — there is no undo, and the store file is the only copy.

The ladder still behaves as you described it. Answering one card right on four consecutive due
days, and then wrong once, moves it like this:

```
after right answer #1: interval=1 due=2026-08-30
after right answer #2: interval=3 due=2026-09-01
after right answer #3: interval=7 due=2026-09-05
after a wrong answer:  interval=1 due=2026-08-30
```

All of it lives in one file you can open and read — `~/.recall.json`, or wherever `RECALL_FILE`
points — and hand-editing that file is still how you move a card's schedule, since you declined a
command for it. The full test suite is 101 tests and passes on the merged trunk.
