## Context

**WI-0004, round 1, question 1 of 1 — and it is the only one. That is all of them for now.**

This is the item you asked for when you accepted the flashcard tool: *"being able to delete a
card I added by mistake."* Refining it threw up one decision that is yours and nine that are
not, so you are getting one question rather than a batch.

**What was decided without asking you**, so you can see it and object if any of it is wrong:
the command is `recall delete <number>`, taking the card's number exactly as `recall list`
already prints it, and one number at a time. Wrong argument counts, a number that names no card,
and an unreadable store file all behave the way `add` and `review` already behave — a message on
stderr, a non-zero exit, and nothing on disk touched. Those are naming, wording and exit codes,
which is the category you handed over when you said *"whatever you think is best, you know this
better than I do"* on where the card file lives; re-asking you would be pretending not to have
heard that.

**One thing you should know while you answer, because it is an assumption and not a decision
you made:** a deletion is final. There is no undo, no trash and no way to get a card's earned
schedule back — a card on the 30-day rung deleted by mistake starts again from nothing if you
re-add it. Nobody asked for undo and adding it would be scope you did not request, so it is
written into this item's `## Out of scope`. Say so if that is wrong.

The thing that makes this a real question rather than a technical one: `recall delete` is the
first command in this tool that destroys something. Everything else adds, shows or updates.

## Question

When you delete a card, should the tool do it straight away, or stop and ask you first?

## Options considered

- **A — delete straight away, and confirm what you did.**

  ```
  $ recall delete 3
  Deleted card 3.
  ```

  Consequence: one command, no keystrokes. If you type `3` when you meant `4`, card 3 is gone
  before you see anything, and the line above is the first you know of it. `recall list` is
  right there to check the number first, and mostly you will be deleting a card you added
  seconds ago.

- **B — show you the card and ask before deleting.**

  ```
  $ recall delete 3
  3	die Katze	the cat
  Delete this card? [y/n]
  y
  Deleted card 3.
  ```

  Consequence: this is the only option that actually stops the mistake — you see the card's two
  sides before it goes. You pay one extra keystroke every single time, including the ninety-nine
  deletions where you had the right number. It costs nothing technically: `review` already reads
  whole lines rather than taking over the terminal, so `printf 'y\n' | recall delete 3` works and
  the criteria stay checkable from a script.

- **C — delete straight away, but show the card's two sides in the confirmation.**

  ```
  $ recall delete 3
  Deleted card 3: die Katze / the cat
  ```

  Consequence: no extra keystroke, and you find out immediately when you deleted the wrong
  thing — which at least tells you what to re-type. It does not prevent anything; the card is
  already gone when you read the line.

- **Recommendation: C.** Every choice you have made on this tool has gone to the smaller thing —
  both card sides on one line rather than a prompt, no decks, no stats, *"that's all it needs to
  be"* — and a prompt on a command you run to fix your own typo is the sort of friction that
  makes people stop using a tool. The loss a prompt would prevent is bounded and small in the
  case you described: a card *added by mistake* has no schedule worth protecting, and re-adding
  it costs one command. C gives you the evidence without the friction.

  **Choose B instead if the card you are worried about deleting is an old one** — one that has
  climbed to the 30-day rung over a couple of months. That history is the one thing in this tool
  that cannot be re-typed, and if losing it by a mistyped digit would actually annoy you, then
  the keystroke is worth it and the recommendation is wrong.

## Answer

[human] C — just delete it and tell me what got deleted. I'm only ever going to run this right
after I typo'd something, I don't need a prompt in my way for that.
